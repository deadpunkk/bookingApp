## Что произошло по времени

Reflog Git сохранил последовательность действий:

| Время | Событие |
|---|---|
| 14:30:23 | В `feature/react-frontend` создан правильный коммит `ae2897b` |
| 14:30:45 | Выполнено переключение с `feature/react-frontend` на `main` |
| 14:30:59 | В `main` создан ошибочный коммит `a289813` |
| 14:32:57 | `a289813` отправлен в `rfcseLocal/main` |
| 14:34:49 | Выполнено переключение обратно на `feature/react-frontend` |

Причина понятна: до переключения правильные исходники фронтенда были tracked-файлами feature-ветки. В старой `main` их еще не было, поэтому при checkout они исчезли из рабочего дерева. При этом локальные `node_modules` и `dist` остались на диске как неотслеживаемые файлы.

В старой `main` отсутствовал frontend `.gitignore`, а корневой `.gitignore` еще не исключал `node_modules` и `dist`. Последующий `git add .` добавил все эти генерируемые файлы, после чего появился коммит на 5 975 файлов и примерно 1,7 миллиона строк.

## Как исправить внутренний remote

Удаленный remote пока не изменялся. Это намеренно: переписывание `main` может затронуть других разработчиков.

### Рекомендуемый вариант

Когда `git.rfcse.local` снова доступен:

1. Отправить ошибочный коммит в отдельную backup-ветку.
2. Отправить правильный коммит в новую recovery-ветку.
3. Проверить recovery-ветку в Git-сервере.
4. Только после согласования заменить `main` с помощью `--force-with-lease`.

Пример команд для проверки перед изменением:

```bash
git ls-remote --heads rfcseLocal
git log --oneline --graph --decorate --all
git status
```

Безопасные новые ветки можно создать без переписывания существующей истории:

```bash
git push rfcseLocal a289813:refs/heads/backup/main-with-node-modules-20260722
git push rfcseLocal ae2897b:refs/heads/recovery/correct-source-20260722
```

После проверки и отдельного подтверждения замена main может выглядеть так:

```bash
git push \
  --force-with-lease=refs/heads/main:a2898139c5ddac6f16ec3c312b696684f099d778 \
  rfcseLocal \
  ae2897ba03df302756d93417ac5d65f473878ce4:refs/heads/main
```

`--force-with-lease` безопаснее обычного `--force`: операция пройдет только в том случае, если удаленный `main` все еще указывает на ожидаемый ошибочный коммит. Если кто-то уже отправил новую работу, Git остановит операцию.

### Вариант без переписывания истории

Можно сделать merge правильной feature-ветки в `main`, затем удалить `node_modules` и `dist` из индекса новым коммитом. Рабочая версия станет правильной, но ошибочный объект на 111 МБ навсегда останется в истории remote. Для этого случая переписывание одного свежего ошибочного коммита обычно чище.

## Чего сейчас не делать

До подтвержденного remote backup не следует выполнять в исходном каталоге:

```text
git reset --hard
git clean -fdx
git branch -D feature/react-frontend
git push --force
docker compose down -v
```

Первые три команды могут удалить локальную работу или единственную понятную ссылку на нее. Обычный `--force` способен затереть новую чужую работу. Последняя команда относится не к Git, но удаляет Docker volume с рабочей SQLite-базой.
